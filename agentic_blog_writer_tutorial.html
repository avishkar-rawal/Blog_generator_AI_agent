Agent memory

State is the shared workspace

Every node receives a state object and returns updates. The state is the agent's working memory for one blog run.

class State(TypedDict):
    topic: str
    mode: str
    needs_research: bool
    queries: List[str]
    evidence: List[EvidenceItem]
    plan: Optional[Plan]
    sections: Annotated[List[tuple[int, str]], operator.add]
    merged_md: str
    image_specs: List[dict]
    final: str

Inputs

topic and the initial empty fields come from the UI.

Updates

Nodes add research, a plan, section text, image specs, and final Markdown.

Reducer rule

operator.add lets parallel workers append their section results into one list.

Decision making

1. The router chooses the path

The router is a small decision-making agent. It classifies the topic into a mode and proposes queries when freshness matters.

closed_book

Evergreen concepts and fundamentals. Skip web research and go directly to planning.

hybrid

Mostly evergreen, but current tools, models, or examples improve the article. Research is enabled.

open_book

Volatile subjects such as latest news, rankings, prices, or policy. Recent evidence is required.

Structured decision

The model returns a validated RouterDecision: mode, boolean, reason, and queries.

g.add_conditional_edges(
    "router", route_next,
    {"research": "research", "orchestrator": "orchestrator"}
)
Tool use

2. Research is conditional, not automatic

When research is requested, the graph calls Tavily for each router-generated query, normalizes results, and asks the LLM to produce a clean evidence pack.

Evidence state
  • Each item keeps title, URL, snippet, source, and optional publication date.
  • Open-book mode filters evidence using the configured as-of date and recency window.
  • Workers are instructed to cite only evidence supplied by the graph for current claims.
Planning

3. The orchestrator creates a production plan

The orchestrator does not write the whole blog. It creates a structured plan that makes the work divisible and testable.

Plan(
  blog_title="...",
  audience="backend and ML developers",
  tone="technical",
  blog_kind="tutorial",
  tasks=[
    Task(id=1, title="...", goal="...",
         bullets=[...], target_words=320),
    ...
  ]
)

5-9 tasks

Enough coverage without making the plan unmanageable.

Concrete bullets

Workers know exactly what to explain, compare, build, or verify.

Quality flags

Tasks can require research, citations, or a code sketch.

Parallel generation

4. Fan-out: one worker per section

The plan is transformed into LangGraph Send messages. Each worker receives one task plus the shared context.

Plan
↘
Worker 1
intro
→
Worker 2
math
→
Worker 3
code
Parallelism is the important agentic pattern: the orchestrator delegates independent work rather than asking one model call to produce a giant document.
  • Each worker outputs only one Markdown section beginning with ##.
  • Workers receive blog kind, tone, audience, task bullets, evidence, and recency rules.
  • Each result carries its task ID so the reducer can restore the intended order.
Writing contract

What each worker is told to do

Coverage

Cover every bullet in order and stay within the target word range.

Scope

Follow the blog kind. A news roundup should discuss events and implications, not drift into a tutorial.

Grounding

For open-book or citation-required tasks, cite only the supplied evidence URLs.

Code

If a task requires code, include a minimal working sketch rather than vague pseudocode.

section_md = llm.invoke([
    SystemMessage(content=WORKER_SYSTEM),

The reducer is itself a subgraph:

merge_content
      ↓

  • merge_content creates the complete draft in stable section order.
  • decide_images may insert up to three exact placeholders such as [[IMAGE_1]].
  • generate_and_place_images replaces placeholders with Markdown image links and saves the final file.
Images and persistence

Two model integrations, two responsibilities

Text model

The configured ChatGroq client creates routing decisions, evidence packs, plans, sections, and image plans.

Image model

google-genai calls Gemini gemini-2.5-flash-image using GOOGLE_API_KEY_image.

OUTPUT_DIR = Path(__file__).resolve().parent / "generated_markdowns"

What is Streamlit?

Streamlit turns Python into a web app

Streamlit is a Python framework for building interactive data and AI interfaces without separately writing a frontend in React, JavaScript, or HTML.

Rerun model

When a user interacts with a widget, Streamlit reruns the script and preserves selected values in session state.

Widgets

st.text_area, st.date_input, and st.button collect user input.

Layout

Sidebar, tabs, columns, expanders, status boxes, and download buttons create the interface.

Python-native

The UI and backend share Python objects, so the app imports the compiled LangGraph directly.

Mental model

Why this is agentic AI

Perceive

Read the user's topic, date, and available context.

Decide

Route to research or skip it; choose the content mode.

Plan

Create a structured set of writing tasks and constraints.

Act

Search the web, invoke workers, call the image API, and write files.

Coordinate

Pass state between nodes and merge parallel outputs.

Recover

Use fallbacks and graceful image failure blocks so the article can still be delivered.

It is not autonomous in the human sense: its behavior is constrained by schemas, prompts, graph edges, API availability, and file paths.

Debugging guide

Where failures usually appear

Before the graph

Missing GROQ_API_KEY, TAVILY_API_KEY, or GOOGLE_API_KEY_image; wrong model or dependency.

During routing/planning

Model does not support structured output, schema is rejected, or the request is blocked by the provider.

During research

No Tavily key/results gives an empty evidence list; open-book filtering may remove undated sources.

During images

Image key/model/quota/safety issue; the exception is converted into an article failure note.

After success

Relative paths, missing output folders, or stale Streamlit state can make a correct result look absent.

Debug in order: check environment variables without printing secrets, test a simple model call, inspect graph logs, then inspect output paths.

The Streamlit app collects a topic and displays progress, while the LangGraph agent decides what to research, builds a plan, delegates section writing, merges the results, optionally creates diagrams, and persists a downloadable Markdown blog.
